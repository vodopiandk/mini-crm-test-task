# Мини-CRM для заявок агентства

Тестовое задание: CRM, куда попадают лиды из Telegram-бота и вручную, с тегами и фильтрами.

- **Живой MVP:** https://mini-crm-test-task-production.up.railway.app
- **Бот:** @agency_leads_test_bot

## Что работает

- Telegram-бот собирает заявку: `/start` → имя → контакт (кнопка «Поделиться номером» или текст) → запрос → подтверждение. Лид появляется в CRM с источником «Бот». `/cancel` сбрасывает диалог.
- Ручное добавление лида через форму (источник «Вручную»).
- Теги: создать, назначить и снять у лида, фильтр списка по тегу (и по источнику).
- Статус лида (Новый / В работе / Готово), карточка лида, история сообщений (пока пустая, задел под Telegram Business).
- Вход по паролю. Список обновляется каждые 7 секунд.

## Что сознательно не сделано

- Обычный Telegram-аккаунт через Telegram Business (п.2 задания). Подход описан в документе с наброском: события `business_connection` и `business_message`, дозапись сообщений в таблицу `messages` к тому же лиду. Таблица и карточка лида уже готовы под это.
- Роли и несколько пользователей (сейчас один общий пароль), воронки и канбан, ответы клиенту из CRM, уведомления, аналитика, импорт и экспорт.

## Стек

Node.js 22, Express, better-sqlite3, grammY (long polling), vanilla JS без сборки. Один процесс: веб-сервер и бот.

## Запуск локально

```bash
npm install
cp .env.example .env   # заполнить переменные
npm start              # http://localhost:3000
```

Переменные окружения:

- `PORT` — порт веб-сервера (по умолчанию 3000)
- `ADMIN_PASSWORD` — пароль входа в CRM
- `SESSION_SECRET` — секрет для подписи cookie-сессии
- `BOT_TOKEN` — токен бота. Если не задан, бот не стартует, веб-часть работает
- `DATA_DIR` — папка для базы SQLite (по умолчанию `data/` в корне проекта)

## Деплой

Сейчас развёрнуто на Railway: сервис из GitHub, постоянный том на `/data`, переменные в разделе Variables. Инструкция для собственного VPS (systemd, nginx, certbot) — в `DEPLOY.md`.

## Структура

- `src/index.js` — точка входа: веб-сервер и бот
- `src/db.js`, `src/migrate.sql` — база и схема
- `src/leadsRepo.js` — создание лида, общее для API и бота
- `src/routes/` — REST API: лиды и теги
- `src/bot/` — бот и состояние диалога в БД
- `public/` — веб-интерфейс
- `DECISIONS.md` — развилки и почему выбрано так
- `CLAUDE.md` — стек и команды для работы с проектом

## Тестирование

Автотестов нет. Проверено вручную и сценариями: API через curl, интерфейс в браузере, диалог бота через подстановку апдейтов, сквозной сценарий (бот → лид → тег → фильтр) в живом Telegram. Следующий шаг — автотесты.
